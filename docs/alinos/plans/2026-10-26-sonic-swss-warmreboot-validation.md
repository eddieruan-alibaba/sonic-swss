# SONiC SWSS Warmreboot Validation Implementation Plan

> **For agentic workers:** Use /alinos.subagent-dev (recommended) or /alinos.executing-plans to implement this plan task-by-task.

**Goal:** 为 `ribfib_3_wb_ai` 的 NHG 热重启建立组件、真实进程、设备状态和物理流量的分层验证证据，不将文档完成或用例存在误报为验收通过。
**Architecture:** 组件层扩展现有 GTest；集成层采用专用可丢弃 DVS、真实 fpmsyncd/helper/Redis 和确定性 TCP FPM 测试端。接收侧调试观察与无调试器性能运行分离；设备层按预先冻结的版本、授权、拓扑和业务预算执行，复用本地证据与判定逻辑，不新增生产接口。
**Tech Stack:** C++/GTest、Autotools、Python 标准库/unittest/pytest、DVS/Docker、Redis/swsscommon、GDB/MI、现有设备与流量仪只读导出接口。

## 统一红绿与缺陷处理规则

1. **新增工具的红绿**：先加入具体断言并运行指定目标；应因缺少新函数/能力失败，而不是环境错误。按子计划实现最小测试辅助能力，再运行同一测试证明绿。语法检查不能代替该测试。
2. **产品回归的红绿**：断言写的是规范结果。首次失败要记录命令、退出码、提交、输入、预期与实际，排除构造器/夹具错误后标记产品 FAIL；不得反转断言、加入 skip/xfail 或自动修改生产代码使其通过。
3. **已知风险不预判实际失败**：DELETE、原始缓存、PIC 内存表、共享引用、占用、parser、信号路径都有源码风险；只有实际运行证据才能说明某例复现。确认失败后，受影响任务与验收关卡保持未完成，另起修复评审；独立工具和诊断可继续。
4. **优先级**：越界/崩溃/破坏已有状态先处理，其次引用、标识、恢复与停机正确性，最后性能。内存安全失败的输入不得直接搬上真实共享设备。
5. **环境失败**：可信依赖、SAI 配置、符号、DVS 协议能力不足记 BLOCKED，不是测试 RED，也不是通过。保留 TLS 校验，不自动卸载 SAI、修改容器权限或规避告警。
6. **提交检查点**：每个可独立验证的任务组先复核 diff 与测试证据；只有用户另行授权后才通过 `/alinos.commit` 提交。不能把“频繁提交”理解成本次计划命令已授权提交；失败不能被记录为全绿提交。

## 统一结果与证据接口

每个运行目录由执行方指定在仓库外或既有忽略目录，不把设备配置、原始日志或凭据提交到 Git。运行记录至少含 `run_id`、`parent_run_id`、`case_id`、`purpose`、`expected_outcome`、`source_revision`、镜像/依赖版本、时间单位、`assertions`、`status`、证据路径和不适用/阻塞原因。重试使用新编号，不覆盖历史。

- 状态为 `PASS / FAIL / BLOCKED / NOT_RUN / NOT_APPLICABLE`；聚合顺序 `FAIL > BLOCKED > NOT_RUN > PASS`，全不适用的组不能输出 PASS。
- pytest 的 skip 只负责避免执行不具备前提的代码；同步结果记录必须标明 BLOCKED 或经批准的 NOT_APPLICABLE，不能把 pytest 退出 0 当验收通过。
- `RECONCILED`、函数返回、发送完成、`restore_count`、finalizer 退出和两张相同快照均不能单独证明完整热恢复。
- 独立期望不得调用 Assist 或同一个活管理器的 `setEntry()`。NHG/PIC 语义、精确表示 ID 保持、SAI OID 语义、写事件保持各自判定。
- 调试观察与性能运行分别给 run_id；不同运行的时间轴和消息消费证据不能拼为一次运行。
- 判流前用 `traffic_evidence_status()` 核对冻结流清单、非空发送和完整接收窗口；缺流、空发送或窗口不完整记 BLOCKED，`sequence_metrics([], [])` 的零指标不能当零丢包 PASS。
