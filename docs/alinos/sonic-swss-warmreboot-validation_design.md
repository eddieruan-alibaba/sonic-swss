## 被测架构与持久化边界

`RouteSync` 持有 `NhgWarmRestartAssist`，后者引用 NHG 管理器并独立维护恢复状态。路由 helper 的应用状态键是 `bgp`，NHG Assist 的应用状态键是 `fpmsyncd-nhg`，二者的容器名均为 `bgp`；不能以进程名 `fpmsyncd` 代替路由状态键。

`APPL_STATE_DB/NHG_FULL_STATE_TABLE` 混合正常回读与停机保存记录，不是完整、权威的重建快照。正常回读不写地址族，停机保存只覆盖符合条件的 RIB 项及分配器信息，旧键可能残留。加载消费有效的 Sonic ID/PIC 关联等元数据，并读取旧 `APPL_DB/NEXTHOP_GROUP_TABLE` 字段值向量；保存的 JSON 不参与重建，实际依赖图来自 FPM 重放。因此损坏保存 JSON 与损坏 FPM JSON 必须分开测试。

恢复期拦截 NHG 5000/5001、普通路由新增/删除、SRv6 VPN 路由 3000/3001 和 resolve-via 6000。localSID 1000/1001、PIC context 2000/2001 不在缓存集合。结束顺序是 NHG 恢复、路由回放、resolve 回放、原 suppression 处理和路由恢复核对；三类队列只保持各自内部顺序，不保证跨类型全局时序。

空路由表使路由 helper 直接完成；NHG Assist 仍在恢复时依靠主定时器结束，不能承诺 EOIU 快速完成。NHG 完成状态早于路由和 resolve 回放结束，单独出现 `RECONCILED` 不等于完整恢复或数据库已可见。

## 分层验证架构

| 层级 | 职责 | 必要边界 |
|---|---|---|
| 第一层：编译与组件 | 可信 Linux 环境编译真实守护进程，运行现有及拟新增 GTest、全量模拟测试回归。 | 保留告警门槛；模拟测试目标的 fake helper 不证明真实主循环行为，须满足无 SAI 时生成模拟测试目标的配置条件。 |
| 第二层：真实进程集成 | 专用可丢弃 DVS，真实 fpmsyncd、helper 和 Redis，由确定性 TCP FPM 测试端替代 Zebra。 | 验证定时器、EOIU、空表、保存、重连；不证明真实 Zebra、系统重启编排或物理数据面。 |
| 第三层：设备状态 | 授权隔离设备，实际 BGP/Zebra、swss、syncd 和系统 warmreboot。 | 冻结版本、拓扑与平台，核对真实热恢复而非冷启动回退，以及恢复后的增删改能力。 |
| 第四层：物理流量 | 外部仪表持续测量静态保持和动态收敛业务。 | DVS、进程存活、前后快照和恢复后连通性不能替代丢包及中断测量。 |

各层按自身前置条件取得证据。设备、规模或流量预算未确定不阻塞组件工作；相关执行能力不足则阻塞对应子例，不能直接写数据库替代真实协议链路，也不能默默排除 SRv6/PIC 后声称全功能通过。

## 真实进程测试端与因果观察

第二层测试端与 fpmsyncd 位于同一网络命名空间，连接既有 `127.0.0.1:2620`；采用 FPM v1/type 1、四字节头、网络字节序长度、四字节对齐和不超过 16384 字节的合法帧，载荷为完整 netlink 消息。使用库兼容 JSON、匹配 ID 和真实 ifindex，覆盖 TCP 分片与合帧，并持续排空响应以避免背压；每次重连重放完整状态。

专用夹具通过 Supervisor 停止并确认 Zebra 不会竞争连接，独占 EOIU 写入，退出时恢复自己改变的服务状态；仅清理本夹具的资源，不清空共享 Redis。TCP 测试端、序列化器、独占夹具和观察控制器均是后续待实现能力，不是现有功能。

恢复轮次标识为 `(run_id, process_incarnation, accept_ordinal)`；同进程重新接受连接不意味着内存重置。输入截止点必须有接收侧缓冲追加或实时处理完成的证据，并早于 `onWarmStartEnd()` 入口；`send()` 返回、等待固定时间、关闭连接均不是消费屏障。

选用隔离小规模测试中的外置 GDB/MI 符号返回观察，关联轮次与载荷摘要，核对状态机、队列长度增量和新增项，防止提前返回误算入队。不增加生产确认协议、控制端口或测试钩子；缺符号或合法调试能力时相关断言为阻塞，不自动改权限。调试运行只证明因果；恢复期限、性能和流量必须另用无调试器运行测量，不把两次运行的证据混作同一次观察。

## 独立判据、共享对象与标识

小规模用例以显式语义期望和有序事件账本作判据，真实生产者以配置和业务账本作判据，无重启参考实例仅作交叉核对。禁止调用 Assist 或同一活管理器的 `RIBNHGEntry::setEntry()` 生成预期：后者可能增加共享引用，临时对象析构不会回退，既污染状态又复制被测缺陷。

语义正确性与标识保持分开验证。下一跳、接口、权重按关联元组比较；SID 顺序、主备角色、重复成员数量不能丢弃。固定合法表示、完整字段匹配的未变化对象须保留可匹配旧 Sonic ID；RIB 改号或成员序列重排另设子例，仍要求语义正确，但当前精确字段匹配不保证任意等价表示保留 ID，必须记录未匹配和对象重建，不能据此推导无损。

两条路由引用同一 RIB NHG 不等于管理器共享 Sonic 对象。共享/PIC 拓扑使用符合 received SRv6 条件的多个 RIB NHG，公共下一跳相同而 VPN SID 不同，并加入组合 PIC。NHG 字段相同不证明 PIC 相同；保留 PIC 数字也不证明内存表重建。必须验证 PIC 查找、恢复后组合创建、删除单个共享者、删除最后共享者和资源释放。

NHG 与 PIC 分配器属于不同命名空间，跨类型同号合法；各类型的活 ID 必须非零且不碰撞。覆盖低分配计数、仅 APP_DB 存在的 ID、旧记录残留和删除后的占用释放，不要求计数回退。数据库写操作按表、键和阶段分类：禁止固定表示静态对象不必要的删除重建，不禁止合法状态上报或收敛写入；缺事件证据时“无删除重建”子断言为阻塞，不能用两张相等快照替代。

## 场景覆盖、首次恢复与退出契约

保留 19 个父场景：C01-C10 覆盖组件、回放与异常输入，L01-L05 覆盖真实生命周期，S01-S04 覆盖设备与流量。支持范围内的正向组合必须包含 IPv4/IPv6、默认及非默认 VRF、普通/封装/SRv6 路由各自的 suppression 开关、真实共享/PIC、6000 连续撤销与恢复、空表和同进程重连；详细设计明确父场景下的必选子例，不依赖任意挑选少量组合。

正常冷预热后的首次及后续 warmreboot 均须真实热恢复，不人工补计数掩盖首轮问题。故意缺少 `restore_count` 单列为负向场景，按固定依赖版本判断安全拒绝或冷回退，不能计入热恢复成功次数。源码中的计数增加只说明检查发生，不能代替完成证据；实际 finalizer 等待的应用集合和服务期限须从运行环境核对。

停机期望按阶段区分：完整工作状态须保留后续恢复所需数据；首次等待连接且没有新图时不要求写空快照；恢复中或同进程重连的部分内存不得覆盖旧完整状态。所有阶段仍要求在冻结的停机期限内退出、无未处理 EINTR，并具有必要保存与刷新证据。

每个负向用例在执行前明确目的与可接受结果。预期的安全拒绝或降级可以使负例通过，但非空健康期望未恢复不能仅凭完成状态通过；已知实现缺口在健康输入下造成错误仍判失败，来源已有不是豁免理由。

## 时间、流量与结果判定

区分加载至逻辑回放完成的 `T_logic`、加载至必要刷新且期望状态可见的 `T_restore`、系统重启开始至预声明就绪点的 `T_system`。统一时间基准；轮询只能提供区间，区间上界在预算内才通过，下界已超预算则失败，跨越预算边界记为测量精度阻塞。

流量按每条流、每轮记录丢包、中断、重复与乱序，静态保持和受控撤销分别统计。建议前后各至少观察 60 秒稳定期，但这不是性能承诺；丢包预算、恢复期限、中断上限和仪表精度必须在执行前冻结，预算缺失不得签署性能达标。

最小拓扑通过后进入冻结规模；连续三轮逐轮判定，不以平均值掩盖单轮失败。三轮只提供有限重复证据，不证明长期无泄漏；确定性对象、引用、占用残留属于错误，RSS、CPU 和耗时按冻结的运行契约判定。

结果区分通过（PASS）、失败（FAIL）、阻塞（BLOCKED）、未运行（NOT_RUN）和不适用（NOT_APPLICABLE）。不适用须有范围依据；聚合优先级为失败、阻塞、未运行、通过，不能用观察缺失遮蔽已知失败。重试使用新运行编号并关联旧记录，不覆盖失败历史。

## 风险、证据与执行输入

源码已确认的风险路径包括：恢复阶段跳过 NHG DELETE；重复初始化不清原始队列；恢复与正常 parser 校验不一致；临时预计算可能增加共享引用；复用 PIC ID 未重建 PIC 内存表；按 Sonic NHG ID 索引的保存信息可能合并 PIC 关联；旧保存键、占用和 PIC 清理不完整；部分退出路径只刷新而不保存。上述路径需要专项测试，尚不能声称其设备影响已复现。

各层运行清单冻结源码、镜像摘要、架构、依赖版本和能力；第三、四层另需平台、拓扑规模、业务预算、授权窗口与恢复方案。兄弟仓库 `sonic-swss-common@472a425` 和 `sonic-buildimage@fd4421b29` 仅为版本限定的源码参考，不等于实际部署版本。缺执行输入阻塞相关关卡，不再作为未决设计问题。

证据以运行编号关联事件账本、原始日志、退出码、测试结果、阶段观察、数据库/路由/硬件快照、规范化差异和逐流统计。禁止关闭 TLS 验证解锁构建，不在生产设备注入异常输入，不自动重启共享设备或上传敏感证据；异常时停止后续循环并保留现场，仅按批准方案恢复。

结构性设计问题已闭环；下一阶段在设计审阅后通过 `/alinos.writing-plans` 拆分测试实现与执行准备，不在本轮生成实现计划或开展测试。GBrain 未连接，历史查询未完成，不等同于检索无匹配；旧来源分支的设备结论也不作为当前基线证据。
